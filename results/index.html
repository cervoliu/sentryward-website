Scope & provenance

Read the result in context.

A verdict applies to the recorded input configuration and the verifier’s model. It is not a claim about every shape, execution environment, or version of a library.

How verification works →
What do the result groups mean?

Verified records passed synchronization, memory, and reference-equivalence checks. Reported findings groups potential races, invalid lifecycles, and inconsistent synchronization; these are verifier findings, not necessarily reproduced hardware failures. Inconclusive groups unsupported analyses and time, memory, or analysis limits.

Per-check outcomes are preserved. “Not run” and “Incomplete” do not mean passed. The equivalence contract and definedness information are available in each record.

Are any analyses conditional?

Some records use configured branch decisions. Their verdicts apply only to those scenarios. Open a marked record to see every recorded branch decision.

Warnings and their collection status are reported independently of the overall verdict.

Where does the data come from?

This page serves a versioned copy of the kernel-verification results snapshot. It does not run the verifier or refresh from the source repository in your browser.

Source-file links require access to the source repository. The downloadable snapshot is available here. Recorded file hashes describe the analyzed inputs; files linked at the publishing revision may differ from those inputs.
